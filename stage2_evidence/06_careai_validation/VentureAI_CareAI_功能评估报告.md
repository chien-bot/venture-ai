# 用 CareAI 测试 VentureAI：功能评估报告

日期：2026-09-14。VentureAI 版本：`d3c6e03`；CareAI 版本：`038d329`。本轮只评估，不修改 VentureAI 产品代码。

## 测试材料与方法

- 项目事实基准：[`CareAI_项目测试基准.md`](CareAI_项目测试基准.md)，并上传仓库根目录的 [`CareAI项目书.md`](../../CareAI项目书.md)（9,873 字节）。测试只涉及项目描述和合成材料，没有真实个人健康数据。
- 通过本地 VentureAI API 创建独立测试账号与 CareAI 项目，上传 Markdown 项目书，开展 6 轮对话；每轮原始输入、完整回复、HTTP 状态、耗时和 `run_id` 保存在 [`careai-live-20260914-135948.json`](careai-live-20260914-135948.json)。测试数据库与日常数据库隔离。
- 5 轮为真实模型调用：`qwen/qwen-2.5-72b-instruct`，日志中 `mock_mode=false`。证据分类一轮被规则直接返回，不能算模型质量样本。
- 浏览器检查了学生登录、项目页、聊天页及入门表单，页面加载、导航和前后端连接正常；截图见本目录。后端既有 5 项回归测试通过，前端构建通过。这些通过项只证明基础功能能运行，不代表建议内容可靠。

## 六轮结果

| 测试 | 实际表现 | 判定 |
| --- | --- | --- |
| `coach_initial`，上传文件后复述项目 | 错称 CareAI 是“心理健康筛查与干预平台”，编造 NLP 模型训练和已做用户访谈；要求招募至少 20 位心理亚健康人群。真实材料明确写着成年人非诊断性习惯管理、无真实访谈。 | **严重失败**：项目事实与医疗边界同时失守。`run_3ac45f3de1cb` |
| `coach_competitor_followup`，补充阿福已有习惯目标 | 接受“阿福已有目标”，但继续沿用错误的心理健康产品设定，设计了心理健康筛查对照和招募 30 人，没把此前错误纠正。 | **严重失败**：多轮错误持续传播。`run_04d441b443b8` |
| `evidence_boundary`，F/I/H/S 分类 | 正确指出无来源比例、付费意愿和慢性病早发现不能当事实，模拟反馈仅为 S；但使用了预设回复中的“大学生普遍睡眠不足”，没有准确处理输入里的“八成”量化主张。 | **部分通过**：基本边界正确，具体陈述匹配不足。`run_923e38eee54d` |
| `tutor_psf`，用 CareAI 解释问题—解决方案匹配 | 定义、反例及两个理解问题基本可用；但把尚未验证的 CareAI 方案写成“有效地解决了”用户问题，要求至少 3 位真实访谈，并额外插入无关的 DroneFarm 无人机案例。 | **部分通过**：教学概念可用，事实等级和相关性不足。`run_9a2b81321603` |
| `grader_uploaded_only`，仅引用上传项目书评审 | 给出 R1–R11 分数，却编造“团队背景多样”“订阅和医院分成”“已有财务预测”，还建议临床验证；这些不在项目书里。 | **严重失败**：无法从文件确认的内容被补写成事实。`run_64f61bb47499` |
| `grader_full_document`，完整正文直接输入 | 正确认出非诊断定位和缺少真实用户数据；R1–R11 的结构化详情已写进项目，但文字回复没有按要求逐项列出依据、缺口和建议，仍插入无关 DroneFarm；R8 团队和 R9 PPT 的部分依据缺少材料支持。 | **部分通过**：长文直接输入显著改善定位，但评审输出契约未完成。`run_4b8551e715ea` |

五轮模型调用的非流式耗时为 38.39–69.18 秒，中位数 67.38 秒。网页聊天使用流式通道，本轮没有测量网页首字延迟，不能把这些数字直接当成用户等待时间。

## 跨流程问题与可定位原因

1. **P0｜事实编造与健康边界错误。** 首轮输入的文件预览已经包含“非诊断性”“不提供疾病诊断”“尚处假设验证前期”，回复仍改成心理筛查并编造访谈；追问后继续错误设定。CareAI 课程材料不允许把临床验证和真实健康数据采集当作当前可交付任务。现有提示词虽有证据边界说明，但没有可靠的“答复事实必须对应来源”的阻断检查。
2. **P0｜项目和对话数据缺少接口访问控制。** 在完全不带登录信息时，`GET /api/projects/`、`GET /api/projects/{id}`、`GET /api/chat/history/{id}` 均返回 200；测试列表包含 CareAI 项目，历史接口返回 5 条消息。详见 [`unauthenticated_access.json`](unauthenticated_access.json)。代码中项目列表对匿名用户回退为全部项目，项目详情与对话历史直接返回记录；见 [`projects.py`](../../backend/routers/projects.py) 和 [`chat.py`](../../backend/routers/chat.py)。公开部署前必须处理。
3. **P1｜上传成功不等于完整读入。** 上传接口提取并保存了项目书全文，但 Agent 每个文件只注入前 2,000 个字符、最近 3 个文件，见 [`agents/router.py`](../../backend/agents/router.py)。项目书后半部分的证据边界、团队未知项和隐私缺口容易丢失。完整正文直接输入后定位明显改善，支持“上下文截断是重要诱因”的判断；模型本身仍有编造，截断不是唯一原因。
4. **P1｜纠错与会话记忆不足。** 用户明确补充阿福已有目标、没有真实访谈后，第二轮仍继承上一轮的错误产品画像。需要区分“用户和文件给出的事实”与“Agent 自己上一轮的推断”，并在纠正时撤销被否定的结论。
5. **P1｜评审展示与依据不一致。** 完整正文那轮的 R1–R11 `rubric_full` 存在项目详情中，但非流式聊天回复只返回 `rubric_scores`，文字又没有逐项解释。部分评分依据提到了未提交的团队能力或 PPT。相关路径见 [`chat.py`](../../backend/routers/chat.py) 与 [`grader.py`](../../backend/agents/nodes/grader.py)。
6. **P2｜无关案例和规则误报增加噪声。** 多轮追加 DroneFarm 合规示例，无法帮助 CareAI 项目；Tutor 系统提示词本身包含 DroneFarm，而后处理只加“这是模拟”的提示，未移除内容，见 [`prompts/tutor.py`](../../backend/prompts/tutor.py) 与 [`course_boundary.py`](../../backend/services/course_boundary.py)。H17“用户终身价值虚高”在没有任何 LTV 估算的项目中多次触发，风险名称与现有材料不符。
7. **P2｜证据分类是固定模板而非逐句核验。** F/I/H/S 结果方向正确，但返回了与本次输入措辞不一致的预设例句。见 [`chat.py`](../../backend/routers/chat.py) 的证据审阅短路路径。

## 建议的优化顺序（本轮尚未实施）

1. 先给项目列表、项目详情、文件与会话历史加身份认证和项目级权限检查，确保公开访问不能读取别人的材料。
2. 再加事实基准与回答校验：从用户/文件提取可引用事实，未知项必须说未知；医疗定位、验证状态和团队/收入等关键主张与材料矛盾时阻断回答或要求重试。
3. 改文件读取与引用：长文分块、按问题检索，回答明确标出材料段落；资料不足时不补写。
4. 修复多轮纠错、无关案例重定向与 H 规则误报，再核对 Rubric 每项的可见依据和流式/非流式一致性。
5. 最后用同一套 CareAI 输入复测，再开展真实用户可用性评估。当前 6 轮测试不能推断普遍错误率，也不能代替学生或教师使用测试。
