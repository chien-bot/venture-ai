# CareAI 一页项目立项书 v0.1

## 1. 项目名称与所属方向

**CareAI：面向成年人的非诊断性健康风险教育与习惯管理助手**

所属方向：社会治理和公共服务（健康教育与公共健康促进）。

## 2. 目标用户

首期目标用户为愿意主动记录基础健康数据的成年人，重点关注希望改善睡眠、运动和体重管理习惯的高校成年学生及初入职场的年轻成年人（H）。

不适用人群：未成年人；正在经历紧急或严重不适的人；需要临床诊断、治疗决策或药物建议的人。

## 3. 核心场景与问题

在日常健康自我管理场景中，成年用户需要把零散的身高、体重、睡眠、运动及可选血压/血糖记录转化为下一步可执行的健康行动；但现有做法常是只看单个数值、依赖通用搜索或不连续地记录，导致用户难以理解数据变化、难以形成可持续的行动安排（I）。

CareAI 以输入数据为起点，通过本地可追溯规则生成风险提示，再由受限 Agent 解释已有风险、提出生活方式建议和 7 天行动计划，并保存历史趋势。它不输出疾病结论。

## 4. 问题依据与边界

- F：国家卫生健康委《健康中国行动（2019—2030 年）》将健康知识普及、合理膳食和全民健身列为重点行动，倡导个人提升健康管理能力。
- F：世界卫生组织建议成人每周进行至少 150 分钟中等强度身体活动，或等量活动。
- F：美国 CDC 说明成年人通常需要每天 7 小时或以上睡眠。
- I：将健康记录、规则解释和短期行动计划放在同一流程中，可能降低用户理解健康数据与安排下一步行动的门槛。
- H：首期目标用户会愿意持续录入数据并使用 7 天计划；需在后续获得授权后，通过可用性测试验证。

本阶段**未进行真实问卷、访谈、临床验证、订单或运营验证**。所有用户需求、留存、付费和效果判断均不得当作既成事实。

## 5. 现有做法与不足

| 现有做法 | 可提供的价值 | 本项目拟解决的不足 |
| --- | --- | --- |
| 用户自行查看体检/设备数据 | 获取原始指标 | 指标零散，解释与下一步行动需用户自行整合（I） |
| 通用搜索或通用对话工具 | 快速获得文字建议 | 可能缺少对输入数据、证据来源和非诊断边界的明确约束（I） |
| 不使用任何工具 | 无额外成本 | 难以形成持续记录与前后变化对照（I） |

## 6. 解决方案与价值主张

CareAI 的流程为：

`健康数据录入 → 本地规则生成可追溯提示 → 受限 AI 解释与行动计划 → SQLite 历史记录与趋势对比`

相较于直接让大模型判定健康问题，CareAI 将风险等级固定在本地规则层，把模型限制为解释和行动建议；相较于只展示数值，它提供面向行动的 7 天计划与历史对比。

## 7. 创新假设

1. **规则与生成分层（H）**：将风险判断和自然语言解释分开，可减少模型越权生成疾病诊断或新增风险类别的风险。
2. **指标—原因—建议—行动计划闭环（H）**：将基础健康数据、风险来源和短期行动计划串联，可提高结果的可理解性与行动性。
3. **非诊断边界可见化（H）**：在输入、报告和规则信息中持续展示适用范围与线下咨询提示，可能提高健康教育场景中的使用边界清晰度。

## 8. 初步发展逻辑

潜在使用者为有基础健康管理需求的成年人（H）。初期可在健康教育、校园健康促进或企业健康活动的低风险教学/演示场景验证可用性（H），并在获得合规授权和专业复核后再评估合作、部署与可持续方式。当前没有收入、用户规模、合作或支付意愿数据。

## 9. 关键风险

- 医疗安全：规则阈值和建议文本不应被解释为临床结论；上线前需要相应资质人员复核。
- 数据合规：健康信息属于敏感个人信息，需补充最小化采集、单独告知/授权、存储期限、删除机制和访问控制。
- 证据风险：目前没有真实用户验证，不能夸大使用效果。
- 技术风险：外部模型 API 不可用时，完整 AI 报告无法生成；本地规则接口仍可独立演示。

## 10. 待验证假设与未来方法

| 假设 | 后续低成本验证方法（需先完成授权与合规审查） |
| --- | --- |
| 用户能理解 `normal / attention / high_attention` 的非诊断含义 | 5–8 名成年志愿者完成情境任务后，复述系统边界并记录误解点 |
| 用户能独立完成数据录入和查看报告 | 观察任务完成率、错误输入和人工求助次数 |
| 7 天计划具有可执行性 | 让授权参与者对计划的具体性、负担和可调整性做匿名反馈 |
| 规则解释比仅展示数据更易理解 | 同一模拟数据下比较“仅数值”与“带来源的规则解释”的理解题结果 |
| 隐私告知足以让用户理解数据处理范围 | 让参与者阅读告知文本后回答数据类型、用途、保存与删除方式 |
